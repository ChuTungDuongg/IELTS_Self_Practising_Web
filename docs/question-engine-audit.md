## Compatibility classification and safe consolidation

- **Actively used:** the 15 nonzero types keep canonical IDs, configuration, keys, responses, numbering, renderers and scoring.
- **Shared implementations:** agreement already shares a renderer; matching/features/endings share a renderer/editor; plan/map share a renderer; structured completion and text evaluation already share implementations. Further broad family consolidation would add risk without demonstrated benefit.
- **Small proven duplication:** matching, heading matching and word-list completion repeat the same UUID-valued option select. Share that control only, preserving exact option labels, placeholders, classes, disabled state and callback payloads. Paragraph matching keeps its distinct block-ID choices.
- **Locally unused:** matching_features, form_completion, flow_chart_completion, summary_completion, sentence_completion and short_answer remain supported and offered. They are legitimate IELTS authoring shapes and/or existing transfer fixtures; local absence alone does not establish unnecessary authoring. **No types hidden, deprecated or removed.**
- **Proven obsolete:** none. No schema migration, persisted question conversion, renumbering or data update is justified.

Baseline protection adds one shared fictional JSON contract for every type, consumed by frontend rendering/interaction/serialization/numbering tests and backend validation/normalization/scoring tests. UUIDs, key kinds, response values, multi-slot behavior and immutable fixture input are asserted. Existing legacy normalization, Builder, rich note/table/diagram and transfer suites remain. The v1 ZIP protocol identifier and ID-remapping rules are unchanged.

Baseline before engine changes: **76 backend tests passed** (registry contracts, registry/evaluation, transfer); **69 frontend tests passed** (shared saved contracts, registry and numbering).

## Presentation design and verification

Practice is a UI preference separate from scope, timer, attempt context and Speaking mode. `attempt-presentation.ts` stores only `PRACTICE`/`EXAM` under attempt-UUID and Full-Mock-session-UUID browser keys. Existing `/attempt/:id`, pause/resume and history destinations stay unchanged. `useSyncExternalStore` provides an SSR-safe Legacy fallback before reading storage. For Reading/Listening, a valid attempt preference takes priority over the session preference, then Legacy; Writing/Speaking retain their existing presentation. Preference sync does not create another attempt or autosave queue. Browser preferences do not sync to another device; clearing storage restores the compatible Legacy fallback.

Reading/Listening full-module, focused-unit, classroom-module and Full Mock launches open a glass presentation dialog only after Start is clicked. The cards themselves show no interface selector. Practice is the default; the old Exam interface is labelled **Legacy**, retaining the internal `EXAM` value for compatibility. Two inert desktop-viewport thumbnails render fictional seed passages and questions through the canonical question registry, shared pane/navigation components, real header layout and runner CSS. They show populated radio answers, structured note gaps, text, player controls and navigation rather than skeleton lines. A scaled, script-free iframe keeps desktop media queries accurate; styles and Personalization root attributes synchronize into it, with observer cleanup. No controller, attempt creation, audio element or notification fetching is mounted. The localized sample label makes the fictional content explicit.

Attempt/session creation occurs only on confirmation, so dismissing the dialog starts no timer. Pending confirmation is guarded against duplicate requests; focus stays inside the modal, Escape/backdrop cancel before submission, and focus returns to the start button. Full Mock stores its choice per session so subsequent Reading/Listening modules and reloads inherit it. This follows the user's later request to allow both layouts in Full Mock; its earlier forced-Exam presentation rule was removed. The preference never changes timer/scope/context fields or a backend policy. Listening still passes `audio_policy.allow_seeking/allow_speed` from its payload to the existing player. Writing/Speaking launches keep their existing behavior.

Both presentations keep the existing runner hooks/controller, canonical registry, response values, flags, semantic highlights, revision autosave, submit reconciliation and server-derived clock. Legacy retains its question shell and CSS treatment. Per subsequent user feedback, active Reading/Listening now also retain the full existing BandPilot header (logo, navigation, personalization, notifications, account/logout), in both presentations. A flex workspace reserves the actual header height and gives the runner the remaining viewport, without an overlay or fixed header-height assumption. Writing/Speaking keep their original immersive shell. A separate timestamp-derived wall clock displays `Asia/Ho_Chi_Minh` / GMT+7 in this header, with a deterministic SSR placeholder; it does not feed the exam timer. Practice applies a CSS Module root only when resolved mode is Practice. The shared renderer refactor remains limited to the option control above; no new drag-and-drop behavior is introduced. Additional explicitly requested homepage and Speaking changes are recorded below.

Reading Practice adds paper surfaces, readable sans-serif passage text, green learning markers, account-accent actions, plain question-group ranges from the numbering helper, a persistent navigator and separate scroll containers. `ReadingSplitPane` starts at 50/50, uses pointer capture (including touch), prevents selection during dragging, supports arrows (2%; Shift 10%), Home/End bounds and Enter reset, and reports separator values/controls. ResizeObserver tightens 30–70% limits to preserve approximately 340px per pane where possible. It disconnects on unmount; pointer handlers are element-local. Passage switches retain the same divider instance; answers and clock stay in the parent controller. Below 900px the divider is hidden and the existing Passage/Questions switch keeps both controlled panes mounted. Width is intentionally session UI state, not a database field.

The question strip, previous/next controls and Submit form one centered, width-bounded group. One active-question flag control replaces repeated flag buttons in Practice; saved flags and chip indicators stay intact. A vector close icon is geometrically centered. Active chips use the existing horizontal reveal helper. Visual map/plan/diagram groups retain their image/answer columns on desktop, stacking only below 600px. Toolbars/footer/audio take layout space rather than covering content. The Practice player uses a filled circular vector Play/Pause button, unboxed five-second seek icons, a small speaker and thin range tracks; its accent follows global Personalization CSS tokens live. No introduction-skip action was added, and player state/seek/speed/clip policies remain shared. Existing highlight guidance and the real personalization dialog are the only new tools; no fake Notes or Translation controls. Dark mode uses product surface tokens. All new copy is localized EN/VI.

## Additional user-reported highlight defect

The original `SelectableText` inspected the range synchronously on its own `mouseup/touchend`. A range finalized afterward, or a pointer released outside the span, never triggered another inspection until the next selection. Three deterministic regressions (question, passage, outside release) failed before the fix. The component now coalesces relevant native `selectionchange`/document `pointerup` updates into a frame, using the latest callback. Other spans do no range work; listeners/frames are removed on unmount or read-only transitions. Existing Escape, outside-click, peer and scroll dismissal also suppress stale deferred selections. Confirmation remains required, and UUID targets, semantic offsets, overlap checks and saved text contracts remain unchanged. The 36-case highlight/word-boundary/runner-localization gate passed.
